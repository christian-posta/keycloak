[[_aauth_troubleshooting]]
= AAuth Troubleshooting

This guide helps diagnose and resolve common issues with the AAuth protocol.

== Common Errors

=== "Agent identity not found"

[source,json]
----
{
  "error": "invalid_request",
  "error_description": "Agent identity not found. Request must be signed with HTTPSig."
}
----

**Cause**: The request is missing HTTP Message Signature headers.

**Solution**:
1. Ensure your agent includes the required headers:
   * `Signature-Key`: Contains the key identifier and scheme
   * `Signature-Input`: Specifies signed components and parameters
   * `Signature`: The actual signature bytes (base64url encoded)
2. Verify the signature is being computed correctly
3. Check that all required components are included in the signature

=== "Agent is not allowed by policy"

[source,json]
----
{
  "error": "access_denied",
  "error_description": "Agent is not allowed by policy"
}
----

**Cause**: The agent is blocked by agent policies.

**Solution**:
1. Check the Agent Policies configuration in the Admin Console
2. If using allowlist mode, add the agent URL to the allowed agents list
3. If using blocklist mode, remove the agent from the blocked list
4. Verify the agent identifier matches exactly (URL comparison is case-sensitive)

=== "One or more requested scopes are not allowed"

[source,json]
----
{
  "error": "invalid_scope",
  "error_description": "One or more requested scopes are not allowed"
}
----

**Cause**: The agent requested a scope not in the allowed scopes list.

**Solution**:
1. Check the Allowed Scopes configuration
2. Add the required scope to the allowed list, or
3. Remove the scope from your request if not needed
4. Leave allowed scopes empty to allow all scopes

=== "AAuth protocol is not enabled"

[source,json]
----
{
  "error": "invalid_request",
  "error_description": "AAuth protocol is not enabled for this realm"
}
----

**Cause**: AAuth is disabled for this realm.

**Solution**:
1. Navigate to **Realm Settings** → **AAuth** → **General**
2. Enable the AAuth protocol
3. Save the changes

=== "Token exchange is not enabled"

[source,json]
----
{
  "error": "invalid_request",
  "error_description": "Token exchange is not enabled for this realm"
}
----

**Cause**: Token exchange is disabled.

**Solution**:
1. Navigate to **Realm Settings** → **AAuth** → **Token Settings**
2. Enable the **Token Exchange** toggle
3. Save the changes

=== "Upstream issuer is not trusted"

[source,json]
----
{
  "error": "access_denied",
  "error_description": "Upstream issuer is not trusted"
}
----

**Cause**: The upstream token's issuer is not in the trusted issuers list.

**Solution**:
1. Navigate to **Realm Settings** → **AAuth** → **Trusted Issuers**
2. Add the upstream issuer URL
3. Verify the URL matches exactly (including protocol and path)

=== "Delegation chain depth limit exceeded"

[source,json]
----
{
  "error": "invalid_grant",
  "error_description": "Delegation chain depth limit exceeded (max: 10)"
}
----

**Cause**: The token exchange would create a delegation chain deeper than allowed.

**Solution**:
1. Reduce the number of hops in your delegation chain
2. Increase the max delegation depth in Token Settings (if appropriate)
3. Reconsider your architecture to reduce delegation depth

=== "Auth token has expired"

[source,json]
----
{
  "error": "invalid_grant",
  "error_description": "Auth token has expired"
}
----

**Cause**: The token being used has passed its expiration time.

**Solution**:
1. Obtain a fresh token
2. Use the refresh token to get a new auth token
3. Consider increasing token lifespan if this happens frequently

== Debug Logging

Enable debug logging to get more information about AAuth processing:

=== Using CLI

[source,bash]
----
# Enable AAuth debug logging
./kc.sh start --log-level=org.keycloak.protocol.aauth:DEBUG
----

=== Using Configuration File

In `keycloak.conf`:

[source,properties]
----
quarkus.log.category."org.keycloak.protocol.aauth".level=DEBUG
----

== Verifying Configuration

=== Check Well-Known Endpoint

[source,bash]
----
curl -s https://your-server/realms/your-realm/.well-known/aauth-configuration | jq
----

Expected response:
[source,json]
----
{
  "issuer": "https://your-server/realms/your-realm",
  "token_endpoint": "https://your-server/realms/your-realm/protocol/aauth/token",
  "jwks_uri": "https://your-server/realms/your-realm/protocol/aauth/certs",
  "signature_algorithms_supported": ["Ed25519", "RS256", ...],
  ...
}
----

=== Check Realm Attributes

Using Admin CLI:

[source,bash]
----
./kcadm.sh get realms/your-realm --fields 'attributes(aauth.*)'
----

=== Verify JWKS

[source,bash]
----
curl -s https://your-server/realms/your-realm/protocol/aauth/certs | jq
----

== Testing Signatures

=== Validate Signature Base String

Common signature issues:

1. **Component ordering**: Components must be in the order specified in `Signature-Input`
2. **Quoting**: Component names must be quoted in `@signature-params`
3. **Line endings**: Use LF (`\n`) not CRLF

Example correct signature base:
[source]
----
"@method": POST
"@authority": your-server.example.com
"@path": /realms/your-realm/protocol/aauth/token
"content-type": application/x-www-form-urlencoded
"signature-key": sig=jwt;jwt=eyJ...
"@signature-params": ("@method" "@authority" "@path" "content-type" "signature-key");created=1705123456
----

=== Verify Key Format

Ensure your keys are in the correct format:
* Ed25519: Raw 32-byte public key
* RSA: Standard RSA public key format

== Performance Considerations

=== JWKS Caching

{project_name} caches JWKS responses. If you see stale key errors:

1. Wait for cache expiration (typically a few minutes)
2. Restart the server to clear cache (development only)

=== Metadata Fetching

For cross-server exchange, metadata is fetched on each request. Consider:

1. Network latency to trusted servers
2. Availability of trusted servers
3. Using local servers when possible

== Getting Help

If you cannot resolve your issue:

1. Enable debug logging and collect logs
2. Capture the exact request/response (redact sensitive data)
3. Document your configuration
4. Check for known issues in the project issue tracker
